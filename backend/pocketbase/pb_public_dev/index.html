eiermann — this is the backend, without the app

You are running the lean backend image. It ships no Flutter web build, so there is no UI to serve here — on purpose, because it means a change to a hook or a migration rebuilds in seconds instead of minutes.

This page exists because a bare 404 here looks exactly like a broken deployment, and it is not one.

Working on the UI

Run the app from Flutter, against this backend. You get hot reload, which a web build baked into a container cannot give you:

cd apps/eiermann
flutter run -d chrome --dart-define-from-file=dart_defines/development.json

The --dart-define-from-file is required: on web the app takes its server from Uri.base.origin unless a build-time POCKETBASE_URL says otherwise, and under flutter run that origin is Flutter's own dev server rather than this one.

Wanting the whole app in one container

docker compose -f docker-compose.yml up -d --build

The -f is what skips docker-compose.override.yml and builds the full image, which serves the app at this address instead of this page.

What is here

  • /api/health — liveness
  • /api/eiermann/info — what the client checks before it trusts a server
  • /_/ — PocketBase Admin UI. Look at data with it; never change the schema there. Schema lives in migrations, and a hand edit is a change no other machine will ever have.
